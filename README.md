# Мониторинг и категоризация обращений

Интегрированное приложение команды для обработки нового обращения и аналитики исторических данных. Ветка `feature/final-integration` объединяет backend, интерфейс оператора, импорт Excel, маршрутизацию, поиск похожих обращений, SLA-аналитику и честный fallback категоризации.

## Что уже работает

- загрузка `.xlsx` и `.xls` до 25 МБ;
- автоматический выбор самого большого непустого листа;
- сохранение исходных строк в SQLite с устойчивым `_record_id`;
- просмотр, поиск и открытие исходной записи;
- форма нового обращения;
- категория, уверенность, объяснение и явный статус модели категоризации;
- рекомендуемая линия, объяснение маршрута и похожие обращения из индекса модели;
- явное предупреждение о ручной проверке при недоступности модели или низкой уверенности;
- SLA-сводка: количество и доля просроченных, среднее, медиана, категории и линии;
- состояния загрузки, пустого результата и ошибки для анализа, истории и аналитики;
- интерактивная документация API по адресу `/docs`.

Маршрутизация и поиск похожих обращений подключены к поставляемой модели участника 2. Артефакт категоризации отсутствует: статус `model-missing`, пустая категория, нулевая уверенность и обязательная ручная проверка. Отдельное воспроизводимое обучение и ленивый offline-адаптер описаны в [modules/categorization/README.md](modules/categorization/README.md). Качество реальной классификации пока не подтверждено. SLA-метрики рассчитываются по активному листу загруженного датасета.

## Установка и запуск

Требуется Python 3.11 или новее и Git. Команды для чистого клонирования ветки на macOS/Linux:

```bash
git clone --branch feature/final-integration --single-branch https://git.codenrock.com/codenrock/khakaton-postcode-challenge-ot-pochtatekha/b26-dsai/monitoring-i-kategorizatsiya-obrashcheniy.git
cd monitoring-i-kategorizatsiya-obrashcheniy
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

Для разработки можно добавить `--reload`. Рабочие SQLite-файлы и копии загруженных Excel создаются в `data/runtime/`; каталог не переносится через Git. После клонирования приложение начинает с пустой историей.
При первом запуске дождитесь строки `Application startup complete`: загрузка встроенной модели маршрутизации может занять несколько секунд.

## Проверка рабочего сценария

1. Откройте интерфейс и загрузите `.xlsx` или `.xls` кнопкой «Загрузить Excel». Для воспроизводимой демонстрации используйте комплектный файл `modules/routing/data/raw/Обращения_1931.xlsx` (1 931 строка). Приложение выберет самый большой непустой лист.
2. На вкладке «История и аналитика» проверьте строки, поиск, открытие записи и SLA-блок.
3. На вкладке «Новое обращение» заполните тему и текст. Услуга, компонент и приоритет необязательны.
4. Проверьте категорию и статус её модели, рекомендуемую линию, похожие обращения и предупреждение о ручной проверке.

Комплектный сырой Excel демонстрирует импорт, историю и состояние неполной SLA-схемы. Для полной SLA-сводки загружаемый Excel должен содержать производные колонки `fact_sla_h`, `is_overdue`, `category_grouped` и `resolved_line`; при их отсутствии интерфейс показывает, каких именно колонок не хватает.

Быстрая проверка API после запуска:

```bash
curl --fail http://127.0.0.1:8000/api/health
curl --fail http://127.0.0.1:8000/api/integrations
curl --fail -X POST http://127.0.0.1:8000/api/appeals/analyze \
  -H 'Content-Type: application/json' \
  -d '{"subject":"Не приходит письмо","description":"Письмо зависло в очереди","service":"Корпоративная почта","component":"Доставка"}'
curl --fail -X POST http://127.0.0.1:8000/api/datasets \
  -F 'file=@/полный/путь/к/обращениям.xlsx'
curl --fail http://127.0.0.1:8000/api/datasets/current
curl --fail http://127.0.0.1:8000/api/analytics/overview
```

Страницу записей получают по `GET /api/datasets/{dataset_id}/records`, отдельную запись — по `GET /api/records/{record_id}`. Значения идентификаторов возвращаются импортом и страницей записей соответственно.

## API интеграции

### Категоризация и общий результат

`POST /api/appeals/analyze`

Вход содержит только регистрационные сведения; для категоризации также поддерживается необязательный `component` (компонент услуги):

```json
{
  "subject": "Не приходит письмо",
  "description": "Письмо зависло в очереди и не доставляется адресату",
  "service": "Корпоративная почта",
  "priority": "Высокий"
}
```

Ответ стабилен для frontend и включает:

- `category.category`, `confidence`, `explanation`, `needs_manual_review`;
- `routing.support_line`, `confidence`, `explanation`, `needs_manual_review`;
- `similar_appeals[]` с `record_id`, близостью, категорией, линией и результатом;
- общий `manual_review_required`.

Интерфейсы адаптеров находятся в `app/services/integrations.py`, адаптеры маршрутизации
и поиска — в `app/services/routing.py`. FastAPI lifespan загружает
`modules/routing/reports/routing/assistant.joblib` один раз на экземпляр приложения
(в каждом worker свой экземпляр). Оба адаптера используют общую модель.
Перезапустите приложение после замены доверенного артефакта. Запуск с
`--lifespan off` не инициализирует модель; в тестах используйте `with TestClient(...)`.

Путь модели фиксирован кодом и не принимается из HTTP-запросов, загруженного Excel
или каталога runtime. Пакет сохраняет имя `postcode`, необходимое для joblib.
Зависимости scikit-learn и joblib закреплены под поставляемую модель.

Вход модели — тема и описание обращения. Возвращаются до пяти похожих обращений
из обучающего индекса, независимо от загруженного Excel. Их `record_id` — исходный
номер запроса из модели, а не SQLite `_record_id`; он не предназначен для
`/api/records/{record_id}`. `score` — косинусное сходство TF-IDF, а уверенность
маршрута — некалиброванная оценка модели. Флаг ручной проверки модели учитывается
в общем `manual_review_required`, включая редкие линии и порог модели.

`GET /api/integrations` возвращает для routing и similarity:

- `pending` — startup ещё не выполнен;
- `ready` — модель загружена, оба метода прошли проверку;
- `unavailable:model-missing` — доверенный файл отсутствует;
- `unavailable:model-incompatible` — ошибка загрузки, версии или проверки модели;
- `unavailable:inference-error` — ошибка при выполнении запроса.

При недоступности модель не перезагружается на запросах: маршрут пустой,
уверенность нулевая, объяснение содержит причину, похожих обращений нет,
требуется ручной разбор. Если сбой возник только на этапе поиска, уже полученная
рекомендация текущего запроса сохраняется; последующие запросы используют fallback.
Неизвестные модели слова также могут дать пустой результат при статусе `ready`.
Категоризация и SLA этой интеграцией не изменены.

ID похожих обращений относятся к встроенному индексу модели и не являются ID импортированных SQLite-записей. Поэтому frontend показывает их как ссылочные значения, но не предлагает открыть через `/api/records/{record_id}`.

### Данные и аналитика

- `POST /api/datasets` — загрузить Excel;
- `GET /api/datasets/current` — получить текущий датасет;
- `GET /api/datasets/{dataset_id}/records` — получить страницу исходных строк;
- `GET /api/records/{record_id}` — открыть исходную запись;
- `GET /api/analytics/overview` — сводка и точка интеграции аналитики участника 3;
- `GET /api/integrations` — статус командных модулей.

SLA-сводка сохраняет поля `total_appeals` и `overdue_share` и добавляет
`overdue_count`, `mean_sla_h`, `median_sla_h`, `category_distribution` и
`line_distribution`. При неполной схеме доступные метрики всё равно
рассчитываются, а отсутствующие колонки перечисляются в `missing_columns`.
Полный расчёт ожидает колонки `fact_sla_h`, `is_overdue`, `category_grouped` и
`resolved_line`; при другой схеме интерфейс честно показывает статус «Неполные данные».

## Ограничения и защита импорта

- рабочая модель категоризации и `model.pkl` не поставляются; штатный результат — `model-missing`, пустая категория, 0% и обязательная ручная проверка;
- точность маршрутизации и похожести ограничена поставляемой моделью, а её confidence не калиброван;
- похожие обращения ищутся во встроенном обучающем индексе, не в загруженном пользователем Excel;
- загружаются только `.xlsx` и `.xls` размером до 25 МБ; multipart-тело ограничивается до записи файла на диск;
- проверяются расширение и сигнатура, размер/разреженность листов, число строк, колонок и ячеек, ZIP-структура XLSX, повторяющиеся и служебные заголовки;
- импортированные данные локальны для текущего runtime и не входят в Git.

  models.py                  общие схемы данных

## Правила разработки

- Не использовать итоговое решение, фактическую линию и фактические сроки как признаки нового обращения.
- Не отправлять изменения напрямую в `main`.
- Работать в ветках `feature/*` и выполнять слияние через Merge Request.
- Не коммитить пользовательские Excel, SQLite и содержимое `data/runtime/`; исключение — уже включённый демонстрационный файл `modules/routing/data/raw/Обращения_1931.xlsx`.
