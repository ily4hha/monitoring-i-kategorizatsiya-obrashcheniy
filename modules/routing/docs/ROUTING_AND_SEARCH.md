## Интеграция с интерфейсом

```python
from postcode.routing import Assistant
assistant = Assistant.load('reports/routing/assistant.joblib')
recommendation = assistant.recommend_line('Описание нового обращения')
cases = assistant.find_similar('Описание нового обращения', exclude_id='37811141')
```

Рекомендация: `line`, `confidence`, `needs_review`, `explanation`, вклад слов `evidence`, оценки всех линий `probabilities`. При пустом тексте или отсутствии слов в словаре линия отсутствует, требуется ручной разбор. Уверенность — некалиброванная оценка модели, не измеренная вероятность успеха. Не показывать её как гарантию.

Результат поиска: `id`, `text`, `category`, `line`, `result`, `similarity`, `source_row`, `source_sheet`, `original`. Поле `original` содержит все исходные поля, включая времена линий. По нему интерфейс открывает карточку исходной записи. `line` — линия решения, времена других линий нельзя называть последовательностью маршрутизации. Сходство — косинус TF-IDF, не вероятность. Пустой список означает отсутствие результатов выше фиксированного порога 0.1. Возвращается до пяти результатов, по одному на группу близких текстов.

## Данные и ограничения

- Источник — Excel Sheet0, SHA-256 и сверка с CSV в manifest.json. 34 именованных поля; пустые форматированные столбцы игнорируются.
- Сохранены исходные поля в records.json. В модель входит только «Описание 2». Необходимо подтвердить неизменность текста с момента регистрации.
- Цель — «Кем решен (группа)», фактическая линия решения, а не доказанно оптимальная первоначальная линия. Все 43 категории остаются в области маршрутизации и поиска.
- Используется существующая политика общего разбиения prepare_csv: seed=42, группы лексически близких текстов Jaccard >=0.85 не пересекаются; противоречивые категории и пустые шаблоны выносятся в review. Исключения сужают область оценки; качество на review не измерено.
- Группировка не выявляет все смысловые повторы. Разбиение не временное. Результаты не доказывают качество на будущих периодах.
- Четвёртая линия имеет единственный пример, который при общем разделении попал в test. Модель обучена на линиях 1–3, четвёртую не рекомендует. Пример сохранён в общей оценке как ошибка неизвестного класса; полноценная оценка четвёртой линии невозможна. Рекомендации обученных классов с менее чем 10 примерами всегда требуют проверки. Низкая уверенность не гарантирует обнаружение неизвестной линии.
- TF-IDF обучается только на train. Логистическая регрессия: C=4, выбор class_weight между None и balanced по Macro-F1 validation. Порог выбирается только по validation: максимальное покрытие при точности принятых >=85% и минимум 20 принятых; если такого порога нет, все рекомендации ручные. 85% на validation не гарантирует 85% на test.
- Финальный test не используется для выбора метода или порога. Его повторный запуск не является новой независимой проверкой.
- Индекс содержит только train — и при проверке, и при демонстрации. Test/review не добавляются в историю автоматически.
- «Результат работ» часто содержит только статус. Не генерируем отсутствующее решение; совпадение категории не доказывает полезности найденного случая.

## Выходные материалы

- `assistant.joblib`: модель и индекс.
- `records.json`, `manifest.json`, `shared_split/`: исходные данные, происхождение, единое разбиение и покрытие.
- `metrics.json`: метрики validation/test, матрица ошибок, доля автоматических рекомендаций и базовая модель большинства.
- `examples.json`: первые по исходному порядку удачные, ошибочные и требующие проверки рекомендации.
- `search_review.csv`: воспроизводимая выборка 30 запросов для оценки поиска; 0/1 в relevant/useful и комментарий. Пустая оценка означает «не оценено».
- `retrieval_checks.json`: косвенные показатели поиска для каждого проверочного запроса.

Для экспертной оценки: relevant=1 при одинаковой сути проблемы; useful=1 если случай помогает выбрать действие/линию или содержит применимое решение. Общий статус «Решение предоставлено» сам по себе не является инструкцией. Оценку решения и тематическую близость необходимо различать.
