# Категоризация в стандартном runtime

Поставляемый `model.pkl` (около 3,7 MiB) содержит TF-IDF по словам (1–2) и символьным `char_wb` n-граммам (3–5), LinearSVC и sigmoid-калибровку. `model.json` содержит метаданные, split-хеши, top-15, размеры классов, параметры и реальные метрики; [REPORT.md](REPORT.md) — читаемый отчёт. Всё подходит для Git; веса, GPU, SentenceTransformer и второй venv не нужны.

Из корня репозитория:

```bash
python -m pip install -e '.[dev]'
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

`ClassifierAdapter` загружает доверенный локальный артефакт один раз при создании приложения, проверяет manifest и выполняет пробный inference. `/api/integrations` сразу показывает `classification: ready`. Обучения, subprocess и сетевых загрузок в HTTP нет. При отсутствии/повреждении артефакта приложение продолжает работу с ручным fallback. После исправления артефакта нужен перезапуск.

## Признаки и проверка

Разрешены только `Описание 2`, `Услуга`, `Компонент услуги 1 уровня`. `Вид запроса` читается исключительно как целевая метка. Тема, приоритет, фактическая линия, результат, SLA, сроки и статусы не являются признаками. Один `build_features` используется в обучении и runtime. Пустые значения, регистр, приветствия, числа и URL нормализуются.

Перед split удалены 1 строка без описания, 69 строк с конфликтующими метками одинаковых нормализованных признаков и 60 повторов. Осталось 1 801 обращение: train 1 440, holdout 361. Точные нормализованные признаки не пересекаются; близкие шаблоны могут пересекаться. Top-15 выбраны **после split исключительно по train**, остальные категории объединены в `Прочее / Неопределено`.

Калибровка sigmoid использует out-of-fold оценки трёх train-фолдов. TF-IDF находится внутри pipeline и заново обучается в каждом фолде, затем итоговая линейная модель обучается на всём train. Holdout не участвует ни в обучении/калибровке, ни в выборе параметров и фиксированного порога 0,70. Поставляется именно проверенная модель, без переобучения на holdout. Загрузка Excel через API её не меняет.

## API и ручной разбор

Контракт `POST /api/appeals/analyze` сохранён: объект `category` содержит `category`, `confidence`, `explanation`, `needs_manual_review`, `limitation`. `confidence` — **оценка модели**, не гарантия. Объяснение показывает кандидата, порог и до пяти положительных вкладов слов в линейную оценку; символьные признаки и калибровка также участвуют в решении. Frontend не изменён.

В ручном сценарии `category=null`, `needs_manual_review=true`, причина есть в `explanation` и `limitation`:

- `low-confidence`: оценка меньше 0,70;
- `outside-top-15`: предсказан агрегированный класс за пределами top-15;
- `ambiguous-category`: предсказан слишком общий исходный класс `Прочее` (он входит в top-15 по частоте);
- `insufficient-features`: меньше двух разных содержательных слов из train-словаря; оценка 0;
- `model-missing`, `metadata-missing`, `model-incompatible`, `inference-error`: технический fallback с оценкой 0.

Для низкой оценки/прочего класса сохраняется оценка **кандидата**, а не «вероятность ручного разбора». Отказ по признакам — эвристика, которая не выявляет все бессмысленные тексты. Неопределённость маршрута может дополнительно установить общий `manual_review_required=true`.

## Воспроизведение без второй среды

В том же окружении, что и API:

```bash
python -m modules.categorization.train_categorizer --check-data
python -m modules.categorization.train_categorizer --output /tmp/postcode-retrained/model.pkl
python -m pytest
```

Путь `--output` должен быть новым: CLI не перезаписывает существующие модели. Он создаёт `model.pkl`, `model.json` и `model.report.md`; поставляемый читаемый отчёт сохранён как `REPORT.md`. Seed=42, один процесс, фиксированные параметры. Для точного воспроизведения версии обучения записаны в `model.json`; стандартная установка закрепляет scikit-learn/joblib. Версии Python/NumPy/SciPy записываются, но их точное совпадение не блокирует runtime: совместимость проверяется загрузкой и пробным inference.

Joblib загружает только доверенный путь оператора/поставки; пути из HTTP или загруженного Excel не принимаются. Metadata сверяется с содержимым артефакта, старый формат от эмбеддера отклоняется. При изменении sklearn нужно переобучить и проверить модель. `notebook.ipynb` — исторический эксперимент, не используемый runtime.
